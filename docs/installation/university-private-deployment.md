# 高校私有部署指南

本文用于在高校校园网、实验室或学院服务器中部署 New API，适合科研助手、校内知识库和课程服务试点。

## 推荐架构

```text
校园网 / VPN
    ↓
学校统一认证（CAS / LDAP / OIDC）
    ↓
Nginx 或 Kubernetes Ingress（HTTPS）
    ↓
New API
    ├── PostgreSQL 或 MySQL
    ├── Redis
    ├── 校内模型服务（可选：vLLM / Ollama）
    └── 外部模型 API（可选）
```

应用、用户、权限、配额和审计日志建议放在校内。模型按数据敏感度分流：普通代码问答可以调用外部模型，未发表论文、学生信息和科研资料优先使用校内模型。

## 最小试点配置

适用于一个学院、2 个实验室、50～100 名师生的试点：

- 应用服务器：4 vCPU、8 GB 内存
- PostgreSQL：2～4 vCPU、8 GB 内存
- Redis：1～2 GB 内存
- Nginx：独立虚拟主机或 Ingress
- GPU：仅在运行校内模型时需要

如果首期只转发到外部模型 API，应用服务器不需要 GPU。

## 部署步骤

1. 准备校内 Linux 虚拟机或 Kubernetes Namespace，并分配固定内网地址。
2. 生产环境使用 PostgreSQL 或 MySQL，不建议继续使用 SQLite。
3. 配置数据库、Redis、HTTPS 域名和备份目录。
4. 部署 Go 服务与 `web/dist` 前端产物。
5. 通过 CAS、LDAP 或 OIDC 接入学校统一身份认证。
6. 按学院、实验室、课程建立用户组，并限制可用模型、Token 配额和并发数。
7. 配置日志留存、管理员双因素认证、文件上传限制和模型调用审计。
8. 先以一个学院或实验室试点，确认权限、费用和数据流向后再扩大范围。

## 安全基线

生产环境至少设置：

```text
SESSION_COOKIE_SECURE=true
TRUSTED_PROXIES=<明确的反向代理地址或网段>
```

同时必须启用 HTTPS、数据库自动备份、管理员 2FA、敏感 Prompt 脱敏、外部模型域名白名单和最小权限管理。不要把完整学生信息、未公开科研数据或密钥写入普通业务日志。

## 模型分流建议

| 数据类型 | 推荐模型位置 | 默认策略 |
| --- | --- | --- |
| 公开资料、代码问题 | 外部 API 或校内模型 | 可外发，但保留审计 |
| 未发表论文、实验数据 | 校内模型 | 禁止外发 |
| 学生个人信息、项目敏感资料 | 校内专用模型 | 单独用户组和配额 |

首期建议上线“科研文献与校内知识库助手”，再扩展到课程助教和校园客服。
